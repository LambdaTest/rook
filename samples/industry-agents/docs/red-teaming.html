An agent can sound helpful while exposing a record, bypassing an approval or claiming a payment that never happened. Rook connects the conversation to evidence you can inspect.

Start with a business rule.

“Only the customer’s own records.” “No settlement without approval.” “No success message without a receipt.” Turn that rule into a test, challenge it, then check what changed.

Follow one request all the way through

Choose the audience’s starting point

QE: review the requirements and agent connection. Developer: include the agent source and inspect its tool boundaries. Both paths open interactive Rook.

Run a focused challenge

Explore, generate and review a role-play or prompt-injection scenario. Test the profile, run with --test, and retain the conversation identifier. Each new scenario starts with separate business state.

Inspect the local report and artifacts

Follow the customer request into the reply, tool arguments and trace. A read-only MCP verifier inspects the same conversation’s receipts without repeating the business action.

Repair, rerun and compare

Check ownership, approval, capacity and allowed destinations in the tools. Repeat the same reviewed test against the updated version; inspect any changed criteria before comparing results.

Read the action as well as the answer

The recorded healthcare attack refused an override persona, but still booked the full 11:00 slot. The appointment receipt exposed the capacity failure. Refusal wording alone did not establish safe behavior.

A blocked export and a safe answer are separate checks. A refusal in one conversation does not establish universal protection. Complete provider usage is needed for cost judgments; illustrative speed and token budgets are not product guarantees.

Try the insurance example

Start insurance-agent for QE or insurance-agent-code for Developer. In Rook, use /report and inspect the run files. For optional hosted review, /sync, execute a new shared run, then /ui.
